 0. COMO SE LEVANZA LOS PROCESOS (3 procesos, no 1)
--------------------------------------------------------------------------------
   # Proceso 1 - API principal
   cd Backend && npm run dev        # nodemon server.js
   # Puerto: la variable PORT de Backend/.env, o 3002 si no existe.
   # dotenv@8 lee .env del DIRECTORIO DE TRABAJO, no del script: por eso el
   # "cd Backend" es obligatorio. Si arrancas desde la raiz con
   # "node Backend/server.js", el .env NO se carga y el proyecto usa los
   # valores hardcodeados de connection.js (ver BLOQUE 1).

   # Proceso 2 - API del blog (proceso aparte, sin ningun npm script)
   cd Backend && node blogServer.js
   # Puerto 3100 escrito a mano en el codigo (ver BLOQUE 4).

   # Proceso 3 - Frontend React
   cd Frontend && npm start         # create-react-app, puerto 3000

   # El frontend depende de que Backend/configure.js exista: el backend hace
   # require('../frontend/configure'). Si en la instalacion nueva se despliega
   # solo la carpeta Backend, el proceso NO arranca (MODULE_NOT_FOUND).
   #   ARCHIVO  -> Backend/server.js  (lineas 13 y 14) y Backend/util.js (linea 3)
   #   ACTUAL   -> const { API_CONEXION } = require ('../frontend/configure');
   #               const { JWT_JSON } = require('../frontend/configure');
   #   POR QUE  -> MongoDB y la llave JWT viven en un archivo del arbol FRONTEND.
   #   OPCION A -> mantener Frontend y Backend como carpetas hermanas (lo simple).
   #   OPCION B -> mover la configuracion a Backend/configure.js y corregir los
   #               tres require para que apunten a './configure'.

 BLOQUE 1. BASE DE DATOS SQL SERVER (mssql)
================================================================================
 1.1 Backend/.env
     Las variables se leen en Backend/db/connection.js (lineas 5-18) y tambien
     en Backend/server.js (linea 1373) para armar la conexion JDBC que usa
     JasperStarter. Las dos rutas deben apuntar al mismo servidor.

     # Conexion principal del backend (mssql)
     SQL_USER=<USUARIO_SQL>                # hoy: sa  -> no usar "sa" en produccion
     SQL_PASSWORD=<CONTRASENA_SQL>
     SQL_SERVER=<SERVIDOR_O_IP>            # hoy: localhost
     SQL_DATABASE=<BASE_DE_DATOS>          # hoy: NOM_ALPLA
     SQL_PORT=1433                          # puerto de la instancia

     # Cifrado del canal SQL Server
     # OJO: solo el valor exacto "true" activa estas opciones.
     # "True", "TRUE", "1" o "si" cuentan como FALSE y la conexion falla o
     # queda insegura.
     SQL_ENCRYPT=false
     SQL_TRUST_SERVER_CERTIFICATE=true

     # OBLIGATORIO agregar en la instalacion nueva (hoy no existe en el .env):
     # Puerto de la API principal. Si no se define, server.js usa 3002.
     PORT=3002

 BLOQUE 6. CATALOGO DE REPORTES (base de datos)
================================================================================
     La lista de reportes que ve el usuario sale de la tabla rep_reporte, no de
     la carpeta Reports. server.js (listAvailableReports, linea 1064) cruza esa
     tabla con los archivos .jasper existentes.

 6.1 Tabla rep_reporte
     # Un reporte aparece en el portal solo si cumple las dos condiciones:
     #   1) existe una fila en rep_reporte
     #   2) el nombre del archivo existe en Backend/Reports
     #
     # Para registrar un reporte:
     #   INSERT INTO rep_reporte (rep_id, rep_nombre, rep_descripcion, rep_tipo, rep_adicional)
     #   VALUES (47, 'MiReporte.jasper', 'Texto que ve el usuario', 1, NULL);
     #
     # reg_nombre debe coincidir EXACTAMENTE con el nombre del archivo
     # (incluida la extension .jasper, sin subcarpetas).

 6.2 Columna rep_adicional (filtros que pide cada reporte)
     # Si el reporte necesita que el usuario elija esquema y periodo:
     UPDATE rep_reporte SET rep_adicional = 'inc_esquema_periodo' WHERE rep_nombre = 'Volante_pago.jasper';

     # server.js:1061 (FLAG_PLANILLA_FILTROS) interpreta esa marca y activa los
     # selects de Esquema y Periodo, y exige p_esquema / p_periodo para generar
     # el reporte. Ese mismo par de parametros ($P) debe existir en el .jasper.
     # Varias marcas se pueden separar por coma: 'inc_esquema_periodo,inc_hdv_id'

 6.3 Tabla rep_parametros (parametros fijos de cada reporte)
     # Valores estaticos del reporte (p_nit, p_nombre_empresa, p_url_logo,
     # p_fecha_ini, etc.). Se leen al generar el reporte (getReportParams).
     # Los registros con rep_id = 0 son parametros globales.
     # Los de tipo rpa_tipo = 'S' se ignoran a proposito: su valor es dinamico
     # (p_emp_codigo lo inyecta el backend segun el usuario de sesion).
     # Es una tabla de Gnosis compartida con otros sistemas: no inventar filas
     # nuevas sin coordinarlo con el area de nomina.

 6.4 Tablas de recursos humanos (esquema SQL obligatorio)
     # La base SQL debe tener, con los mismos nombres de columna:
     EMP_EMPLEADO, HDV_HOJAVIDA, planilla, rep_reporte, rep_parametros,
     BAN_ENTIDAD, EPS_ENTIDAD, AFP_ENTIDAD, ARP_ENTIDAD, CCF_ENTIDAD,
     GRP_GRUPOLAB, STC_SUBTIPOCOT, COT_TIPOCOT, CDT_CENTROTRA, SCC_SUBCENTRO,
     CDC_CENTROCOSTO, DEP_DEPENDENCIA, CAR_CARGO.
     # La union usuario<->empleado es HDV_HOJAVIDA.HDV_CORREO = correo del login.
     # planilla se consulta por planilla.empleado = EMP_CODIGO, y por
     # planilla.esquema (char(2)) y planilla.periodo (numeric) para el volante.
